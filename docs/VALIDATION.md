# Initial release validation

Date: 2026-09-12. Profile: AutoUpgrade **26.5.260807**.

## Automated checks

- 55 Node.js built-in tests passed: rendering, import preservation, duplicate and malformed input handling, scope and inheritance, mode requirements, selected semantic constraints, migration mappings, project round trips and command quoting.
- 7 Python standard-library tests passed: deterministic build, embedded offline assets, final CSP hashes, script order, profile checks and absence of network APIs or browser persistence in application code.
- Both JavaScript source files passed `node --check`.

Local tools: Node.js 24.18.0, Python 3.12.5 and OpenJDK 17.0.20.1 on macOS ARM64. CI reruns the automated checks on Linux.

## Comparison with the supplied JAR

Five synthetic configurations generated by the rule engine were passed to the supplied JAR's isolated file parser: upgrade, non-CDB conversion, unplug/plug, refreshable PDB and patching. All exported assignments were read back with matching keys and values. The earlier profile investigation included 18 additional parser probes; see [the profile methodology](PROFILE.md).

These checks exercise file parsing, not the complete semantic pipeline or database execution. They are not CI tests because the Oracle binary is not distributed with this project.

## Browser checks

Checked in the Codex in-app browser against the local HTTP site:

- Desktop layout at 1280 × 720 and mobile layout at 390 × 844; no document overflow at the mobile width.
- Basic analyze configuration, live preview and static error gating.
- COMPATIBLE/restore-point dependency: export blocked on an invalid combination, enabled after correction.
- Import of a synthetic `.cfg`, preserving comments, line order and an unknown parameter; editing a SID updates the line diff and keeps its inline comment.
- Unplug/plug PDB mapping with source preservation and a copy clause; refreshable PDB link and interval; explicit mapping refresh.
- Clipboard contents matched the preview, including per-PDB settings and imported inline comments.
- Optional read-only WebMCP inspection accepted an empty argument object and rejected unexpected arguments.
- No application warnings or errors appeared in the inspected browser console.

The download button was exercised, but the in-app automation did not report completion of a Blob download. The written file was therefore not verified through that browser; clipboard export was verified. Direct `file://` execution of the offline edition was blocked by the browser URL policy. The offline artifact was checked statically, including its embedded assets and CSP hashes; opening it as a local file was not browser-tested.

## Remaining environmental validation

No database connection, AutoUpgrade analyze/fixups/deploy run, patch download or Oracle home creation was performed. Database topology, upgrade feasibility, TDE, RAC, Data Guard and actual recovery remain server-side checks. A green AUGUR status means only that its implemented static checks pass.
